# Zendo × MCP 連携（設計メモ）

- 方針確定: 2026-07-30 / **ツール仕様・権限確定: 2026-07-31**。実装は未着手
- 目的: 他のAIアプリ（claude.ai / Claude Desktop / MCP対応クライアント）から、Zendoのタスクを**リアルタイムに参照・操作しながら会話**する

想定する会話例:
- 「今日はこのタスクが終わっていません」
- 「Inboxにこのタスクが7/20からずっと残っています。いつやりますか？」
- ユーザー「じゃあ明日やる」→ AIが期日を明日に更新

## 1. 権限方針（確定・2026-07-31）

**渡す**: 参照全般 / タスク追加 / 完了・完了取り消し / 期日変更 / 習慣を当日タスク化
**渡さない**: 削除・破棄・タイトルやメモの書き換え・Project変換・習慣マスターの編集

| 判断 | 結論 | 理由 |
|---|---|---|
| 削除（delete） | **渡さない** | ユーザー指定。取り返しがつかない |
| 破棄（drop） | **渡さない** | 削除ではないが破壊的（繰り返しが終了し子も巻き込む）ため削除と同様に扱う |
| 完了の取り消し（uncomplete） | 渡す | 誤完了のリカバリ手段。繰り返しの次回生成も巻き戻るので破壊的でない |
| 期日クリア（Inboxへ戻す） | **繰り返し以外なら渡す** | 「一旦Inboxへ」は再スケジュール会話に必要。ただし繰り返しタスクは期日クリアで `recurrence_rule` も外れる（DB制約）ため、**繰り返しタスクに対しては拒否**する |
| 習慣 | 参照＋当日タスク化まで | 習慣サポートは会話の価値が高い。習慣マスターの編集は渡さない |

## 2. ツール仕様（確定）

### 参照

| ツール | 引数 | 返すもの |
|---|---|---|
| `get_status` | — | 今日＋Inbox＋期限超過のサマリ。**会話の起点用に1呼び出しで状況を把握**できる |
| `list_today` | — | 今日の未完了/完了。期限超過・時刻超過を含む |
| `list_inbox` | — | 未仕分け。**滞留日数**付き |
| `list_upcoming` | `days?` | この先の予定 |
| `get_task` | `id` | 単体詳細（子ToDo・リマインダー・繰り返し設定） |
| `find_task` | `query` | タイトル部分一致で**候補を複数返す**。自動で1件に決めない（4章） |
| `list_habits` | — | 習慣＋継続指標（ストリーク・今週/今月の進捗）＋今日の候補か |

### 操作

| ツール | 引数 | 備考 |
|---|---|---|
| `create_task` | `title, due_date?, due_time?, tags?, parent_id?` | 期日＋時刻を指定すると期限ちょうどの通知が自動で付く（既存仕様） |
| `complete_task` | `id, expected_title` | 繰り返しなら次回生成＋チェックリスト複製が走る |
| `uncomplete_task` | `id, expected_title` | 次回生成も巻き戻る |
| `set_due` | `id, expected_title, due_date, due_time?` | `due_date: null` は期日クリア。**繰り返しタスクには拒否** |
| `add_habit_today` | `habit_id, expected_title` | 習慣を当日タスク化（instantiate）。同日二重生成はDB制約で不可 |

## 3. 返り値スキーマ

生データに加え、AIが自発的に状況を語れる派生値を含める（計算は `src/lib` の読み取りヘルパ側）:

- `overdue`（期限超過か。当日で `due_time` 超過も含む）/ `overdue_days`
- `stale_days`（Inbox滞留日数。`created_at` 起点）
- `postponed_count`
- `is_recurring` / `is_habit` / `has_children`
- 習慣は `streak` / `streak_unit` / 今週・今月の進捗

書き込みツールは**操作後の対象タスク（タイトル込み）を返す**。AIが「『包丁を研ぐ』を完了しました」と事実ベースで報告できる。

## 4. ガードレール（対象の取り違え防止）

AIが別のタスクを操作しないための多層防御。

1. **書き込みは必ずUUID指定**。タイトル文字列での操作は受け付けない
2. **`expected_title` 必須**（既存タスクを操作する全ツール）。サーバー側でDBの実タイトルと突き合わせ、**不一致なら実行せずエラー**（実タイトルを添えて返し、AIに再確認させる）。AIの記憶違い・ID取り違えをここで止める
3. **`find_task` は自動で1件に決めない**。候補が複数なら全部返し、ユーザーに選ばせる。0件なら明示的に0件と返す
4. **事前条件チェック**: 既に完了済みなら「既に完了しています」、存在しない/破棄済みなら明示エラー。黙って成功扱いにしない
5. **一括操作を作らない**。1呼び出し＝1タスク（bulk completeは実装しない）
6. **クライアント側の承認**（MCPクライアントがツール実行ごとに確認）を前提に運用する

`expected_title` の照合は前後空白を除いた完全一致。絵文字・記号もそのまま比較する。

## 5. アーキテクチャ

MCPサーバーは**薄いアダプタ**に徹する。ドメインロジックは既存 `src/lib/*` を再利用し、MCP層に業務ロジックを書かない（[[feedback_backend_portability]] と整合）。

```
AIアプリ ──MCP(Streamable HTTP)──▶ /api/mcp (薄い) ──▶ src/lib (既存) ──▶ Supabase
```

**stdio専用サーバーは作らず、最初からNext.jsのHTTPエンドポイント1本で作る**（2026-07-31変更）。理由: 同じ実装をローカル（`http://localhost:3000/api/mcp`）でも本番でも使え、二重実装を避けられる。ローカル検証時にstdio接続が必要なら `mcp-remote` 等のブリッジを使う。

## 6. 認証

- ローカル検証: 不要（localhost）
- リモート最小: 固定 Bearer トークン（自分専用・URL秘匿）
- リモート本格: OAuth 2.1（claude.ai コネクタが期待する標準）
- **注意**: Zendoは実質単一ユーザーで service key 直叩き。**無認証で公開すると全タスクが露出する**。リモート公開時は認証を必ず入れる

## 7. 副作用の注意（AIが引き起こす）

- `complete_task`（繰り返し）→ 次回インスタンス生成＋チェックリストの子を複製
- `complete_task`（習慣インスタンス）→ ストリークに加算
- `set_due` で期日クリア → 繰り返しが外れる（**そのため繰り返しには拒否**）
- `create_task` で期日＋時刻 → 期限ちょうどの通知が自動付与

## 8. "リアルタイム" の実体

MCPは**会話ターンごとにツールを呼んで最新を取得**する＝実質リアルタイム。ただし Zendo→AI への push ではない。「毎朝AIから棚卸しを促す」ような能動的リマインドは、AIアプリ側の定期実行と組み合わせる別の話。

## 9. 残タスク

1. `src/lib` にMCP用の読み取りヘルパを整理（滞留日数・超過判定・サマリ組み立て）
2. `/api/mcp` に Streamable HTTP のMCPエンドポイントを実装（参照ツール）
3. 操作ツール＋ガードレール（`expected_title` 照合・事前条件）を実装
4. ローカル（localhost）で Claude Desktop から会話テスト
5. 認証（Bearer）を入れて Vercel にデプロイ
6. claude.ai 等へコネクタ登録し E2E 確認。必要なら OAuth 2.1 へ
