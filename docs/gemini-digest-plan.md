# Gemini を定時報告に入れる計画

作成: 2026-09-26。docs/line-plan.md（LINE連携の元計画）は経緯として書き換えず、ここに差分の決定を置く。

## 0. 決定事項

- 定時報告1通の中身を **①Geminiの声かけ ②Geminiが選ぶ注目タスク ③従来のテンプレ** の3段にする。push数は増やさない（1枠1通のまま）
- ①: 完了数・消化度合いへの称賛、軽いお世辞、励まし。**line-plan.md 2章「完了した件数には触れない」は①に限って撤回**（何が本人に効くかを試している段階のため。③のテンプレは据え置き）
- ②: 重要度・放置日数・メモの薄さ・先送り回数・期限の近さを総合して「今こそ手をつけたい1件」と次の一手（話を聞く／分解する）を選ばせる。**line-plan.md 9.2 の4択（引っかかっているタスク）は②に統合**し、Gemini が失敗した時の代替としてだけ残す
- 候補は **Todayの未完了＋Inboxの未仕分け**（放置日数が効くのは主にInboxのため）。**習慣と繰り返しタスクは除く**（決まってやるルーティンで、試し出しでは毎日のチェックリストに分解を勧めてきた）
- **メモ本文も渡す**（充実度を判断材料にするため。1件500字まで）。無料枠の Gemini API はGoogleが入力を改善に使いうる点は承知の上
- 口調: 20〜30代の女性、上下ではなく対等にタスク管理を一緒にやる相棒。責めない・残件数で圧をかけない。**2026-09-26の試し出し後に、くだけた口調から「です・ます調で落ち着いた感じ・褒め方は過大にせず言葉を選ぶ・絵文字は1〜2個」に変更**（「すごすぎる」「天才」が続いて軽く響いたため）。③のテンプレと口調が揃った。続けて**絵文字の個数制限は外した**（生きた文面にするため）
- ①は**挨拶で始めない**（LINEの通知欄は冒頭しか見えないので、「こんにちは」で枠を使わない）
- **残り件数で圧はかけないが、残りの重さは気にかける**: 夕方・深夜の便で、今日の残り時間（24時まで）に対して未完了・期限切れが多ければ、量を絞って休む選択肢を問いかける。材料として未完了の一覧と件数・期限切れの件数・見積もりの合計・残り時間を渡す
- **指示文に例文を置かない**（2026-09-26）: 当初「お疲れのようでしたら、2つくらいだけやって今日は休みますか？」を例に書いたところ、試し出し3回とも言い回しも数字もほぼ同じになった。誘い方の語尾の例（「〜してみませんか」）も同様に、理由の文が毎回同じ語尾になった。意図と判断材料だけを書き、言い回しは毎回変えるよう指示する。「すごすぎる」等の**使わせない言葉**の例は写される心配がないので残す
- Gemini が失敗・25秒で返らない時は ①② を省き、③＋従来の9.2の4択で送る（通知を止めない）。503（混雑）だけは1度やり直す。試し出しの実測では成功時も8〜9秒かかり、当初の10秒では時間切れが出た

## 1. 段階

1. **声かけ＋注目タスク＋記録**（本書 2〜5章）。②のボタンは [ベイビーステップにして]（既存の分解と同じ処理）と [今日はパス]
2. **[話を聞いて]**: 足りない情報を1問ずつ聞き、答えの要点をメモに追記、最大3往復で「分解する？」「期日決める？」を提案。会話中のテキストはタスク登録に回さない。`line_conversations` テーブルで状態を持つ。詳細は段階1の運用を見てから詰める

## 2. Gemini への依頼（段階1）

- 1枠につき1回。テンプレ（③）が「言うことなし」で null の枠では呼ばない（送らない枠でAPIを使わない）
- 候補タスクは `t1` `t2`… の短い参照名で渡し、返ってきた参照名を実在のタスクに引き直す（UUIDを写し間違える・存在しないIDを作る事故を避ける）
- 渡すもの: 枠（平日/休日・朝昼夕深夜）と現在時刻 / 候補ごとに タイトル・メモ（500字まで）・期日時刻・重要度・所要時間・先送り回数・放置日数（作成からの日数）・未完了の子の数・Inboxかどうか / 今日完了したタイトルと件数 / 声をかけたい習慣 / 直近2日に②で選んだタスク（同じものを続けて選ばないため）
- 受け取るもの（responseSchema でJSON固定）: `{ greeting: string, focus: { ref, reason, next: "hearing" | "breakdown" } | null }`
- 検証: greeting が空なら失敗扱い。長すぎれば切る。focus の ref が候補に無ければ focus だけ捨てる
- temperature 0.8（毎回同じ声かけにならないように）
- **深夜の便では、今夜のうちに動けないもの（外出・買い物・人や店の都合が要る用事、時刻の過ぎた今日の予定）を選ばせない**（試し出しで23時に「19時に買いに行く」を選んだため）
- 「話を聞く」が選ばれても段階1のボタンは [ベイビーステップにして][今日はパス] のまま（2026-09-26決定）。今は重要度の高いタスクにメモが無く毎回「話を聞く」になるが、メモが育てば選ばれ方も変わるはずなので様子を見る

## 3. 表示（Flex）

```
greeting（①）
─ 注目タスク（②）: タイトル / 理由 / [ベイビーステップにして][今日はパス]
テンプレ本文（③）＋既存のタスク・習慣ボタン
```

- altText（通知欄）は ① の先頭にする
- ② がある便は既存の9.2の4択を出さない。ボタン数は4択がある時と同じ上限（3件）に抑える（Flex 10KB）

## 4. ボタン

- [ベイビーステップにして] → 既存の `big`（分解して子ToDo化）
- [今日はパス] → 新しい postback `pass`。`line_focus_passes` に（タスク, 今日）を記録し、今日の残りの便ではそのタスクを候補から外す

## 5. データ（マイグレーション）

- `gemini_logs`: Gemini 呼び出しの記録（用途・成否・かかった時間・出力・エラー）。**すべての Gemini 呼び出し**（分解も含む）をここに残す。line-plan.md の積み残し「Gemini使用ログ」を兼ねる
- `line_focus_passes`: [今日はパス] の記録

## 6. 確認

- `/api/cron/line?preview=1` で、送らずに ①② の実際の文面を見ながらプロンプトを調整する。`&at=19:00` で時刻を差し替えられる（夕方・深夜の文面を昼に確かめる）
- プレビューの呼び出しは `gemini_logs` に `kind='digest_preview'` で残し、直近に選んだタスクの判定（`kind='digest'`）に混ぜない
- **Gemini の無料枠は 1日1モデル20回**（太平洋時間0時にリセット）。試し出しを回すとすぐ尽きたため、2026-09-26に有料枠へ切り替えた
- 純関数（プロンプト組み立て・応答の検証と引き直し）にテストを付ける。Gemini 呼び出し自体はテストしない
